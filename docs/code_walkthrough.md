# 代码讲解

这份文档按数据流动的顺序讲一遍代码：原始 CSV → 清洗合并 → 计算 → 出图出表。每一步都写了"为什么这样做"，面试时被问到可以照着讲。

## 1. 整体结构

```
data/raw/          原始下载文件，只读，不改
   │  load.py      读取、清洗、合并
   ▼
data/processed/    合并好的干净数据
   │  analysis.py  单一伙伴国的时间序列分析（发现一）
   │  shift.py     多国份额和转移分析（发现二、三）
   ▼
reports/           Excel 汇总表 + PNG 图
```

`src/knitwear/` 里放的是可复用的函数，`scripts/` 里放的是把函数串起来、一键跑完的脚本。这样分开的好处是：函数可以在 notebook 里单独调用、单独测试，脚本只负责流程。

**原则：原始数据永远不改。** 所有清洗都在代码里做，任何人拿到原始文件重跑脚本都能得到一样的结果，这就是"可复现"。

## 2. `paths.py`：统一管理路径

```python
ROOT = Path(__file__).resolve().parents[2]
RAW_DIR = ROOT / "data" / "raw"
```

`__file__` 是 `paths.py` 自己的位置，往上两级就是项目根目录。这样不管你从哪个文件夹运行脚本，路径都是对的，不会出现"在我电脑上能跑、换个目录就报错"。

## 3. `load.py`：读取和清洗

### `read_comtrade(path)`：读一个文件

1. **`encoding="utf-8-sig"`**：Comtrade 导出的 CSV 开头有一个看不见的 BOM 字符，不去掉的话第一列的列名会变成 `﻿typeCode`。
2. **`dtype={"cmdCode": str}`**：HS 编码必须当字符串读。否则 `6110` 会变成数字，像 `0101` 这种以 0 开头的编码会丢掉开头的 0。
3. **`KEEP` 字典**：原始文件有 47 列，只保留需要的 15 列，并改成简短的英文名，比如 `primaryValue` 改成 `value_usd`。
4. **日期处理**：月度文件的 `period` 是 `202501`，年度文件是 `2025`。代码先看长度再决定用哪种格式解析，所以同一个函数能读两种文件。
5. **`qty`、`net_kg` 里的 0 换成空值**：Comtrade 在"没有报告数量"时写 0。如果当成真的 0，算平均单价时就会出错。

### `load(pattern)`：读一组文件并合并

```python
files = sorted(RAW_DIR.glob(pattern))
df = pd.concat([read_comtrade(f) for f in files])
```

`glob("us_imports_world_hs61_*.csv")` 会找到 2023–2026 四个文件，读完后上下拼成一张表。这就是为什么文件命名规则很重要：命名统一，一行代码就能找全。

**重复检查**：按"日期 + 报告国 + 流向 + 伙伴国 + 编码"检查有没有重复行。如果你不小心把同一年下载了两次，这里会直接报错，不会悄悄把数字算成两倍。

## 4. `analysis.py`：单国时间序列（发现一）

- **`monthly_wide`**：用 `pivot_table` 把长表变成宽表，月份做行、年份做列。这样每一行就是"同一个月在不同年份的值"，方便比较。
- **`yoy`**：`pct_change(axis=1)` 沿着列方向算变化率，也就是同一个月今年比去年变了多少。`fill_method=None` 是为了让缺失月份（2026 年 9–12 月）保持空值，否则 pandas 会拿上一个值去填，算出 0% 的假同比。
- **`annual_summary`**：2026 年只有 8 个月，和完整年份比全年总额是不公平的。所以代码自动找出最新一年有哪些月份，再把每年都只取这些月份求和，得到"同期比较"。

## 5. `shift.py`：份额和订单转移（发现二、三）

### `by_partner(df, hs_code, months)`

还是 `pivot_table`：年份做行、伙伴国做列，值是进口额（百万美元）。`months=range(1, 9)` 时只取 1–8 月，用来做同期比较。

### `shares(table)`：份额

```python
table.div(table["W00"], axis=0)
```

`W00` 是 Comtrade 里"全球合计"的代码。`axis=0` 表示每一行都除以这一行自己的全球合计，得到每个国家当年的份额。

### `change(table, 2024, 2025)`：转移分解

核心是一个比例：

```
某国接走的比例 = 该国增加额 ÷ 中国减少额
```

比如越南增加了 13.2 亿，中国减少了 38.3 亿，13.2 ÷ 38.3 ≈ 35%，就是"越南接走了中国丢掉订单的 35%"。

**要注意这个指标的假设**：它默认其他国家的增长都来自中国的转移。实际上越南本来就在增长，所以这是"上限"式的估计。报告和面试里说清楚这一点，会显得考虑得更周全。

### `index_to_base(table, 2023)`：指数化

把每个国家 2023 年的值都设为 100。规模差很多的国家（越南面料 47.8 亿，孟加拉 15.1 亿）放在一起时，比较的是谁涨得快，而不是谁本来就大。

## 6. 两个脚本

| 脚本 | 用到的数据 | 产出 |
| --- | --- | --- |
| `scripts/run_hs61_analysis.py` | `us_imports_china_hs61_*.csv` | `reports/hs61_summary.xlsx`，图 01–03 |
| `scripts/run_shift_analysis.py` | `us_imports_world_hs61_*.csv`、`china_exports_world_hs60_*.csv` | `reports/shift_summary.xlsx`，图 04–06 |

脚本开头的 `sys.path.insert(0, str(ROOT / "src"))` 是为了让 Python 找到 `knitwear` 这个包。`matplotlib.use("Agg")` 表示不弹出窗口，直接把图存成文件。

运行方式（在项目根目录）：

```bash
.venv/bin/python scripts/run_shift_analysis.py
```

## 7. 面试可能会问的问题

- **为什么用 Comtrade 的美国进口数据，而不是中国出口数据？** 美国进口数据按原产国统计，海关记录更细，而且直接反映美国市场的需求结构。两边的数据因为运费、统计时间和转口贸易对不上，这在贸易数据里很常见。
- **怎么确定是关税导致的？** 现在的分析只能证明"同时发生"。要更进一步，可以用双重差分法：拿没有加征关税的品类或时期当对照组。
- **你怎么保证数据没出错？** 有三点：原始文件不改，重复行检查，以及两次独立下载的中国数据完全一致（最大差值为 0）。
- **如果再给你一周，你会做什么？** 下载 6 位 HS 编码的数据拿到数量，区分"买得少了"和"变便宜了"。
